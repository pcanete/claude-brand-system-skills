# Component Strategy

Checkpoint v0.3.

Component boundaries should follow meaningful visual or behavioral systems.

Create a component when:

- it repeats
- it has independent state
- it owns meaningful responsive logic
- it forms a reusable visual family
- isolated QA is useful

Avoid both extremes:

- one monolithic page component
- atomizing every wrapper

Editorial references may intentionally use irregular one-off compositions.
Do not force them into generic cards or design-system primitives when that
destroys fidelity.
